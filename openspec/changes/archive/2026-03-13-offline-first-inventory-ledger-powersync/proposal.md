## Why

Inventory updates currently depend on online tRPC reads/writes and backend stock calculations, which creates latency, weak offline behavior, and duplicated stock logic across client and server. We need a true offline-first model where local UX is instant, cloud sync is deterministic, and server-side ledger triggers remain the single source of truth for stock integrity.

## What Changes

- Add Supabase PostgreSQL trigger logic for `movement_details` (`INSERT`/`UPDATE`/`DELETE`) that applies signed stock deltas to `items.stock` using parent `movements.type`.
- Move inventory read flows from tRPC queries to PowerSync `useQuery` SQL reads aligned with local SQLite schema and sync-rule camelCase aliases.
- Move movement creation writes from tRPC mutations to local PowerSync SQL writes (`movements`, `movement_details`) with immediate optimistic `items.stock` adjustment.
- Implement `uploadData` in `SupabaseConnector` to upload movement entities while ignoring optimistic `items` stock updates generated by movement flows.
- Remove legacy backend procedures and frontend loading states that existed to support online-first stock recalculation and long-running write UX.
- **BREAKING**: Inventory movement stock consistency shifts from API transaction-time recalculation to DB trigger-driven ledger reconciliation, and frontend write paths become local-first.

## Capabilities

### New Capabilities

- `offline-inventory-ledger-sync`: Defines the end-to-end offline-first inventory write/read/sync contract using PowerSync local SQL + Supabase trigger-based stock reconciliation.

### Modified Capabilities

- `inventory`: Inventory reads migrate to local SQL subscriptions and write UX assumes instant local commit semantics.
- `movements`: Movement creation flow migrates to local append-only ledger inserts; server stock validation/calculation responsibilities are reduced to trigger-enforced integrity.
- `powersync`: Connector upload queue behavior changes to selectively ignore movement-originated optimistic `items` updates while still syncing canonical movement rows.

## Impact

- **Database**: New/updated PostgreSQL trigger function(s) and trigger bindings on `movement_details`; stricter reliance on append-only ledger semantics.
- **Backend API** (`apps/api`): Removal/simplification of stock-calculation and validation procedures previously used by movement/item write paths.
- **Frontend** (`apps/frontend`): Inventory and movement data hooks refactored from tRPC read/write hooks to PowerSync SQL `useQuery` + `db.execute`.
- **Sync Layer**: `SupabaseConnector.uploadData` now enforces source-of-truth filtering to prevent optimistic `items.stock` race conditions in cloud writes.
- **Contracts**: Existing OpenAPI shapes for items/movements remain reference constraints, but operational behavior shifts to local-first execution with eventual cloud convergence.
